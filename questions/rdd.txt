4. flatMap()
Interview difference

map() → one input can produce one output.

flatMap() → one input can produce zero, one, or many outputs.

10. cogroup()
Concept

cogroup() groups values from multiple Pair RDDs having the same key.

rdd1 = sc.parallelize([
    (1, "John"),
    (2, "David")
])

rdd2 = sc.parallelize([
    (1, "IT"),
    (2, "HR")
])

result = rdd1.cogroup(rdd2)

print(
    result.mapValues(
        lambda x: (list(x[0]), list(x[1]))
    ).collect()
)
Hands-on

Create:

Order RDD
Payment RDD

Perform cogroup() using:

Orders
Payments
Interview difference
join()	cogroup()
Combines matching values	Groups values
Two Pair RDDs	Can work with multiple Pair RDDs
Produces paired records	Produces grouped iterables
Common for relational-style operations	Useful when multiple datasets need grouping
11. cache()
Concept

Stores an RDD in memory so that subsequent actions can reuse it.

data = sc.parallelize(range(1, 1000000))

data.cache()

print(data.count())

Interview question

When should we use cache?

When the same RDD/DataFrame is used multiple times and recomputation would be expensive.

13. Broadcast Variables


Used when a small dataset/value needs to be available on all worker nodes.

Example:

Use it:

    (101, "John", 1),

14. Accumulator Variables
Concept

Used for counters and aggregations from executors back to the driver.

counter = sc.accumulator(0)

data = sc.parallelize([1, 2, 3, 4, 5])

def process(x):
    global counter

    if x % 2 == 0:
        counter.add(1)

data.foreach(process)

print(counter.value)

Output:

2
Hands-on

Use accumulator to count:

Invalid records.
Null records.
Negative numbers.
Failed records.
Records satisfying a condition.
Interview point

Accumulator is primarily useful for monitoring/debugging counters, not for implementing core business logic.

Repartition vs Coalesce in Spark
1. What is a Partition?

A partition is a logical chunk of data processed by one Spark task.

For example:

RDD has 4 partitions

Partition 1 → 100 records
Partition 2 → 100 records
Partition 3 → 100 records
Partition 4 → 100 records

Spark can process these partitions in parallel.

2. repartition()

repartition() is used to increase or decrease the number of partitions.

Syntax
rdd.repartition(number_of_partitions)
Example
data = sc.parallelize(range(1, 101), 4)

print(data.getNumPartitions())

new_data = data.repartition(8)

print(new_data.getNumPartitions())

Output:

4
8

Here:

Before:
4 partitions

After:
8 partitions
Important Point

repartition() always causes a shuffle.

4 partitions
      ↓
   SHUFFLE
      ↓
8 partitions

Because Spark redistributes the data across partitions.

3. coalesce()

coalesce() is generally used to reduce the number of partitions.

Syntax
rdd.coalesce(number_of_partitions)
Example
data = sc.parallelize(range(1, 101), 8)

print(data.getNumPartitions())

new_data = data.coalesce(4)

print(new_data.getNumPartitions())

Output:

8
4

So:

Before:
8 partitions

After:
4 partitions
Important Point

coalesce() normally does not perform a full shuffle when reducing partitions.

8 partitions
    ↓
coalesce()
    ↓
4 partitions

This makes it generally cheaper than repartition() for reducing partitions.

4. Main Difference
Feature	repartition()	coalesce()
Purpose	Increase/decrease partitions	Mainly decrease partitions
Shuffle	Yes	Normally no
Performance	More expensive	Generally faster
Data redistribution	Full redistribution	Limited/no redistribution
Can increase partitions?	Yes	Generally not recommended
Can decrease partitions?	Yes	Yes
Use case	Need balanced redistribution	Reduce partitions efficiently
5. Very Important Interview Question
Q: I have 100 partitions and want 10 partitions. Which one should I use?

Usually:

rdd.coalesce(10)

Because you are reducing partitions and don't need a full shuffle.

Q: I have 10 partitions and want 100 partitions. Which one?

Use:

rdd.repartition(100)

Because coalesce() is not designed for efficiently increasing partitions.

6. Why Do We Need repartition()?

Imagine:

Partition 1 → 10 GB
Partition 2 → 100 MB
Partition 3 → 100 MB
Partition 4 → 100 MB

The data is badly distributed.

One task has to process 10 GB, while other tasks process only 100 MB.

This can cause data skew / uneven workload.

Using:

rdd.repartition(4)

Spark redistributes the data.

Before

P1 → 10 GB
P2 → 100 MB
P3 → 100 MB
P4 → 100 MB

       ↓
   repartition
       ↓

P1 → ~2.5 GB
P2 → ~2.5 GB
P3 → ~2.5 GB
P4 → ~2.5 GB

The exact distribution depends on the data.

7. Why Do We Need coalesce()?

Suppose you have:

1000 partitions

but your output file is relatively small.

Writing 1000 partitions can result in many small output files.

You can reduce the number of partitions:

result = rdd.coalesce(10)

Then write the data.

1000 partitions
       ↓
coalesce(10)
       ↓
10 partitions
       ↓
10 output files approximately

This is a common practical use case.

9. Interview Trick Question
Can coalesce() increase partitions?

Technically, Spark's RDD coalesce() has an option to shuffle, so it can be used with shuffle=True:

rdd.coalesce(10, shuffle=True)

But for normal partition increases, the standard recommendation is:

rdd.repartition(10)

because repartition() is specifically intended for redistributing data into the requested number of partitions.
