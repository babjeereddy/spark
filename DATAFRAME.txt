What is a DataFrame?

A DataFrame is a distributed collection of data organized into named columns, similar to a table in a database.

Example:

+----+------+------+
| id | name | age  |
+----+------+------+
| 101| John | 25   |
| 102| David| 30   |
| 103| Smith| 28   |
+----+------+------+
Important characteristics
Distributed
Immutable
Has schema
Organized into rows and columns
Supports SQL operations
Optimized by Catalyst Optimizer
Uses Tungsten execution engine
Supports lazy evaluation
2. What is Dataset?

A Dataset provides the benefits of DataFrame processing with strong typing.

Conceptually:

RDD
 ↓
Dataset
 ↓
DataFrame

In Scala/Java, Dataset is an important API.

Important PySpark interview point

PySpark does not provide a separate typed Dataset API like Scala/Java.

In PySpark:

DataFrame
≈
Dataset[Row]
Interview answer

A DataFrame is essentially a Dataset of Row objects, while a Dataset in Scala/Java can provide compile-time type safety.

3. RDD vs DataFrame vs Dataset
Feature	RDD	DataFrame	Dataset
Structure	Objects	Rows/columns	Typed objects
Schema	No	Yes	Yes
Optimization	Limited	Catalyst + Tungsten	Catalyst + Tungsten
Type safety	Yes	No compile-time type safety	Yes
SQL support	Limited	Excellent	Excellent
Python	Yes	Yes	No typed Dataset API
Performance	Generally lower	Generally higher	High
Interview question

Which one should normally be preferred?

For structured/semi-structured data:

DataFrame

is generally preferred over RDD because Spark can optimize DataFrame operations.

5. select()

With expression
df.select(

6. withColumn()

Used to:

Create a new column
Modify an existing column
Create column
from pyspark.sql.functions import col

df = df.withColumn(
    "annual_salary",
    col("salary") * 12
)
Modify existing column
df = df.withColumn(
    "salary",
    col("salary") * 1.10
)

This creates a new DataFrame because DataFrames are immutable.

where()

Interview question

Difference between sort() and orderBy()?

For DataFrames, they are effectively equivalent APIs for sorting.

16. Join Strategies

⭐⭐⭐⭐⭐

This is one of the most important areas for experienced Spark interviews.

1. Broadcast Hash Join

When one DataFrame is small:

from pyspark.sql.functions import broadcast

result = large_df.join(
    broadcast(small_df),
    "dept_id"
)

Concept:

Large DataFrame
      |
      |
Executors

Small DataFrame
      ↓
Broadcast
      ↓
All Executors
2. Sort Merge Join

Used commonly when both datasets are large and join keys can be shuffled/sorted.

Concept:

Large DF
   ↓
Shuffle
   ↓
Sort
   ↓
Merge

Large DF
   ↓
Shuffle
   ↓
Sort
   ↓
Merge
3. Shuffle Hash Join

Data is shuffled based on join keys and a hash table is built for the smaller side.

4. Broadcast Nested Loop Join

Used for certain non-equi/cross-style join situations and is generally more expensive.

21. Spark SQL

⭐⭐⭐⭐⭐

Spark SQL allows you to use SQL queries on DataFrames.

First create a temporary view:

df.createOrReplaceTempView("employees")

Then:

result = spark.sql("""
    SELECT *
    FROM employees
    WHERE salary > 50000
""")

result.show()
SQL aggregation
result = spark.sql("""
    SELECT
        department,
        COUNT(*) AS employee_count,
        SUM(salary) AS total_salary,
        AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department
""")

result.show()
22. Performance Tuning

⭐⭐⭐⭐⭐

This should be the final module because students need to understand DataFrames, joins, partitions, and transformations first.

Teach these topics:

1. Use DataFrames instead of RDD when possible
RDD
 ↓
More manual optimization

DataFrame
 ↓
Catalyst Optimizer
 ↓
Better optimization opportunities
2. Avoid unnecessary columns

Instead of:

df.select("*")

use:

df.select(
    "emp_id",
    "name",
    "salary"
)

This is column pruning.

3. Filter early

Instead of processing unnecessary records:

df.filter(
    col("salary") > 50000
)

before expensive operations such as joins where appropriate.

4. Use Broadcast Join

If one DataFrame is small:

large_df.join(
    broadcast(small_df),
    "id"
)
5. Avoid unnecessary groupByKey()

For RDDs:

groupByKey()

can move a lot of data across the network.

Prefer:

reduceByKey()
aggregateByKey()
combineByKey()

when applicable.

6. Avoid unnecessary shuffles

Expensive operations include:

groupBy
join
distinct
orderBy
repartition

Students should learn to identify shuffle operations.

7. cache() / persist()

If the same DataFrame is reused:

df.cache()

df.count()
df.groupBy("department").count()
8. Partition tuning

Teach:

df.repartition(10)

and:

df.coalesce(4)

Remember:

repartition()
    → shuffle

coalesce()
    → generally reduces partitions without full shuffle
9. Adaptive Query Execution — AQE

Very important for modern Spark interviews.

Spark can dynamically optimize query execution based on runtime statistics.

Examples include:

Dynamic coalescing of shuffle partitions
Join strategy changes
Handling certain types of skew
